# Первый рабочий Research Bank

Ограниченный этап `R1-FIRST-USABLE-BANK-001`: файл / URL / самостоятельная заметка → сохранение → поиск → точный оригинал → повторное открытие. Это ещё не полный R1, исследовательский процесс или редактор всех типов объектов.

## Запуск на Windows

Из корня проекта с проверенным проектным Python. Системный `python` может указывать на другое окружение без зависимостей:

```powershell
.\.venv\Scripts\python.exe -X utf8 EXPERIMENTS\first_bank\runtime.py setup
.\.venv\Scripts\python.exe -X utf8 EXPERIMENTS\first_bank\runtime.py launch
```

Для повторного запуска можно дважды щёлкнуть `EXPERIMENTS\first_bank\launch_bank.cmd`: он выбирает проектный `.venv` при наличии.

`setup` создаёт отдельный Bank в `%LOCALAPPDATA%\ResearchAndBank`. Семь приватных соседних папок: `bank`, `intake`, `stage`, `cache`, `output`, `source`, `authoring`. Настройка хранится в `config.json` вне Git. Существующая известная настройка переоткрывается; неизвестная или незавершённая БД не сбрасывается. Чтение и запуск ничего не создают. Python должен поддерживать SQLite defensive mode, jsonschema и Tk; локальный фиксированный NTFS проверяется существующими guards. Приложение не меняет права ОС, службы или сеть.

Можно явно указать другое место через `--base 'C:\полный\путь'` во всех командах. Конфигурация закреплена на время открытого окна; для её смены требуется закрыть окно и запустить другую проверенную конфигурацию.

## Сохранение и получение

1. «Новый материал»: выбери «Заметка», «Файл» или «Ссылка», введи название и содержимое.
2. «Сохранить» выполняет проверку и запись одной операцией. Для заметки обязательны название и текст; имя автора необязательно. Форма остаётся при ошибке и закрывается после подтверждения банком.
3. «Поиск» → ввести слово → «Найти». Доступны понятные поля «содержимое файла», «текст заметки», «название» и другие.
4. Строка → «Открыть». Для файла — «Выгрузить файл»: точная приватная копия без запуска содержимого.
5. При UNKNOWN или другом отказе повтор в той же форме продолжает ту же проверенную/запечатанную копию. Ручные этапы и журналы доступны в «Дополнительных инструментах», не нужны при обычном сохранении.

[Отказ сохранения заметки и исправленный пользовательский путь](rechecks/20261010_note_save/NOTE_SAVE_UX_20261010.md). Новые private files и cache создаются с явным владельцем текущего пользователя; ранее найденные пустые admin-owned остатки сохранены отдельно, actual поиск восстановлен без изменения Bank/config.

`auto` считает `.txt`/`.md` текстом UTF-8; для другой extension можно явно выбрать `utf8_text`. Валидность проверяется по всем скопированным байтам, включая последний неполный codepoint. BOM, CRLF и оригинальные bytes сохраняются. Ошибочный UTF-8 не принимается как текст; отдельная новая подготовка в `binary` доступна явно. До 4 МиБ текст индексируется полностью; больший текст до 64 МиБ сохраняется, но поиск честно показывает `size_limit` и доступен по метаданным. Файл больше 64 МиБ отклоняется. Ссылка хранится без скачивания содержимого. OCR/PDF extraction отсутствуют.

Новые подготовки используют `r1-authoring/2`, закреплённый режим и producer version 2. Существующие `r1-authoring/1` сохраняют прежние поля, media type, producer version 1, IDs и точные bytes даже после удаления исходника. Переход профиля не обновляет старые подготовки автоматически.

## Обновление и диагностика

Открытое окно примерно раз в две секунды проверяет компактный read-only сигнал Bank. Внешняя запись обновляет первую страницу списка. Выбранная revision, история, результаты поиска и вкладка остаются закреплены; уведомление сообщает о новых данных. При busy/disconnect прежние строки остаются видимыми. Наблюдатель не восстанавливает горячий журнал записью.

Поиск перестраивается отдельной видимой ограниченной операцией общего worker после сохранения/внешнего изменения или перед поиском. Сам query остаётся read-only. Ошибка/лимит не маскируются как пустой успешный поиск. Обновление выполняется без перекрывающихся worker; закрытие ждёт начатую операцию и отменяет запланированные.

«Диагностика сохранения» читает отдельный append-only журнал попыток. `UNKNOWN`, I/O и busy не превращаются в канонические квитанции. Квитанция `receipt.get` подтверждает фактическое принятие независимо от более поздней неудачной попытки. Отсутствие квитанции или диагностической записи не доказывает неудачу сохранения. Если журнал записать не удалось, известный ACCEPTED/REPLAY сохраняется и показано `ATTEMPT_NOT_RECORDED`.

Приватный запрос через существующий command adapter:

```json
{"protocol":"local-bank-attempt-query/1","operation":"attempt.get","transaction_id":"UUIDv4","before_rowid":123}
```

Первая страница не требует `before_rowid`. Результат сообщает `available`, `not_recorded`, `unavailable` или `incomplete_scan`; продолжение использует `next_before_rowid`. Порядок — вставка, а не часы. За запрос проверяется максимум 4096 строк / 1 секунда, выдаётся до 20 записей. Неполный поиск не выдаётся за отсутствие. Канонические schema/DDL/индексы не изменены.

## Проверенная копия

«Проверенная копия Bank» или:

```powershell
.\.venv\Scripts\python.exe -X utf8 EXPERIMENTS\first_bank\runtime.py backup
```

Создаётся согласованный SQLite backup snapshot в новой приватной папке `output`. Копия переоткрывается; проверяются формат, каталог, SQLite integrity, foreign keys и сохранённые канонические данные в пределах существующего рабочего бюджета. Путь, SHA-256, количество проверенных commits и ограничения показаны явно. `PARTIALLY_VERIFIED` не равен полной проверке. Это не слепое копирование живого файла БД. Отдельные диагностические records не проходят дополнительную семантическую проверку при backup. Сохрани важную копию на другом носителе самостоятельно. Restore, расписание, retention, аппаратная сохранность и полная стратегия R3 пока не приняты.

## Проверки и граница готовности

`python -X utf8 EXPERIMENTS\first_bank\verify.py` запускает сквозные и затронутые headless регрессии в принадлежащих тесту временных папках. Он не открывает GUI основного рабочего стола. Каждому прогону соответствует отдельный файл `evidence/`; прежние неудачные результаты сохраняются.

Установка реальной конфигурации и пользовательская визуальная приёмка фиксируются отдельно в [карточке](../../PLANNING/WORK_ITEMS/R1_FIRST_USABLE_BANK.json) и [receipt](../../PLANNING/WORK_ITEMS/R1_FIRST_USABLE_BANK_RECEIPT.json). Успех тестов сам по себе не закрывает пользовательскую приёмку. Следующая разработка после неё — сохранённая [R1_OBJECT_AUTHORING](../../PLANNING/WORK_ITEMS/R1_OBJECT_AUTHORING.json). Все прежние WinError1314 capability blockers, остальные R1/R2/R3 и сценарии исследования/Watch сохраняются.
