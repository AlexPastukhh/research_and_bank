# Создание материалов — ограниченный локальный компонент R1

Форма создаёт новую запись из файла, ссылки или самостоятельной заметки.
Название и содержимое вводятся в форме; IDs и время выделяются приложением.
Подготовленная запись неизменяема. Новый ввод создаёт новую запись явно.

Порядок: **Новый материал → Подготовить → Опубликовать → Сохранить в Bank**.
Подготовка и публикация не подтверждают сохранение: это делает реальная квитанция Bank.
Кнопка «Подготовленные записи» открывает сохранённую подготовку после перезапуска.
Полная проверенная копия продолжает работать без исходного файла.
Для прерванной подготовки без SEAL нет скрытого повторного чтения исходника;
части сохраняются, дальнейшая подготовка требует явно нового ввода.
При UNKNOWN проверь квитанцию той же записи; повтор сохраняет те же IDs.

Запуск через `authoring_ui.py` использует **существующие** приватные и непересекающиеся
каталоги: `--bank-root`, `--intake-root`, `--source-root`, `--stage-root`,
`--cache-root`, `--output-root`, `--authoring-root`.
Компонент не создаёт Bank, не исправляет разрешения на исходнике и не устанавливает приложение.
Пример команды с отдельно подготовленными тестовыми каталогами:

```powershell
& '<python.exe>' -X utf8 '<repo>\EXPERIMENTS\draft_authoring\authoring_ui.py' --bank-root '<bank>' --intake-root '<intake>' --source-root '<source>' --stage-root '<stage>' --cache-root '<cache>' --output-root '<output>' --authoring-root '<authoring>'
```

Файл копируется потоково; сохраняются точные bytes/hash и имя как метаданные.
Первый профиль допускает выбранный обычный файл на локальном фиксированном NTFS,
один hardlink, без перенаправлений в пути; исходник только читается.
Ссылка сохраняется без скачивания. Заметка хранит текст/markdown и явно указанного
автора user/ai/unknown; модель не выводится автоматически. Просмотр остаётся обычным текстом.

`LIMITS.json` — версионируемый рабочий профиль: 64 МиБ/файл и 256 МиБ/пакет
из действующего контракта; 128 подготовок, 1 ГиБ workspace+source,
1 МиБ UTF-8 заметки с дополнительным ограничением фактических JSON bytes,
512 МиБ работы за запрос и 60 секунд. Ограничения не обрезают исходные данные.
Нет автоматического удаления, исследования, сети, фонового Watch или редактора
существующих объектов/Entity/Collection.

Код подготовки, адаптер исходника и новый presenter/window находятся отдельно;
прежние publisher/controller/SQLite/read/search/UI импортируются без изменений.
`INTENT/SEAL` лежат вне строгого inventory исходного пакета. Публикация повторно
сверяет pinned manifest с SEAL; квитанция читается из Bank независимо от повреждения журнала.
Результаты интерфейса привязаны к исходному tx и поколению выбора; A→B очищает панели.
Общий worker не позволяет сохранить или опубликовать параллельно подготовке.
Отмена кооперативна до SEAL; после него завершается проверка. Закрытие ждёт фактический исход.

Пробы и регрессии: `implementation_20261007/`. Каждый прогон имеет отдельный файл;
неудачные результаты сохранены в истории `ISSUES.json`.
Наличие компонента не принимает полный R0/R1/MVP/production, реальные данные,
hardware/backup/a11y или четыре ранее BLOCKED native reader symlink fixtures.
