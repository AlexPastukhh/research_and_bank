# Создание и редактирование материалов в Bank

Структурированные формы подключены к прежнему окну Bank. Технические проверки и пользовательская визуальная приёмка фиксируются отдельно: [карточка](../../../PLANNING/WORK_ITEMS/R1_OBJECT_AUTHORING.json), [receipt](../../../PLANNING/WORK_ITEMS/R1_OBJECT_AUTHORING_RECEIPT.json), [проверка выполнения](../implementation/COMPLETION_REVIEW.md).

## Запуск

Обычный запуск — `EXPERIMENTS\first_bank\launch_bank.cmd`. Он выбирает прежнюю семикаталожную конфигурацию или явно включённое расширение. Запуск не создаёт каталоги и не меняет настройки.

Явное включение редакторов из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -X utf8 EXPERIMENTS\first_bank\runtime.py setup-objects
.\.venv\Scripts\python.exe -X utf8 EXPERIMENTS\first_bank\runtime.py check
```

Расширение хранится отдельно в `%LOCALAPPDATA%\ResearchAndBank\object-authoring-config.json`; исходный `config.json` сохраняется. Восьмой приватный каталог `object_authoring` хранит журнал новых подготовок. Откат включения: `runtime.py rollback-objects`. Он сохраняет расширенную конфигурацию под новым именем и оставляет все материалы, версии, оригиналы и журналы. Повторное включение явно создаёт/проверяет новое расширение. Прежний Bank продолжает читать сохранённые объекты.

## Пользовательский путь

1. «Новая сущность»: название, вид, альтернативные названия, внешние идентификаторы и связанные материалы.
2. «Новая коллекция»: выберите материалы в Bank и добавьте их в форму. Удаление и стрелки меняют состав и порядок.
3. «Добавить заметку»: выберите материал, задайте текст и автора. Другие материалы можно добавить из основного окна.
4. «Редактировать»: откроются название и прежние поля выбранного материала. Незаполненное поле «Другой файл» оставляет текущий файл. Если поля не изменились и другой файл не выбран, «Подготовить изменения» показывает «Изменений нет» и не создаёт пакет.
5. «Подготовить» → «Опубликовать» → «Сохранить в Bank» → «Квитанция». Подготовка и публикация отдельно от подтверждённого сохранения.
6. «Подготовленные объекты» открывает журнал; одинаковые названия различаются номером строки. «Завершить подготовку объекта» продолжает ту же запечатанную копию. Незапечатанная запись остаётся INCOMPLETE; новый ввод создаётся явно.
7. Если материал уже изменён другим сохранением (STALE_BASE), подготовка сохраняется. Повтор продолжает её же; для новых правок откройте актуальный материал в Bank. При UNKNOWN проверьте квитанцию этой же подготовки.

Основной список показывает материалы по названию и времени сохранения. История открывается отдельной командой; поиск по умолчанию использует актуальные материалы. «Включить историю» — дополнительный явный выбор в поиске. Полные ID, документ и квитанция доступны через «Технические детали»; там же показывается ID подготовки. Обычные формы не требуют понимания object/revision/transaction IDs.

Внутри модель версий сохранена: ссылки закреплены, выбор другой строки не меняет базу открытой формы, прежнее состояние и файл доступны через историю. Повтор сохранения и проверка конфликтов остаются прежними. Первое сохранение проходит по общему механизму, без специального режима для первой версии. Отмена до seal и ожидание завершения при закрытии сохранены. Старые подготовки `r1-authoring/1` и `/2` совместимы.

Названия строк истории/поиска уточняются на существующем рабочем потоке по точной закреплённой ссылке, максимум для 10 строк страницы. Показ названия не заменяет identity. В списках связанных материалов используется ограниченный кеш известных названий; неизвестное имя честно отмечается «название не загружено», а полный pin доступен в технических деталях.

Применение рекомендаций PR-001/PR-003 и проверки: [запись выполнения](../implementation/VERSION_UX_ACCEPTED_20261010.md).

## Ограничения текущего профиля

До 128 записей в отдельном журнале; до 128 элементов каждого списка; 64 МиБ на оригинал. Полный поиск содержимого UTF-8 сохраняет прежний предел 4 МиБ: более крупные оригиналы сохраняются с честным `size_limit`. Текст заметки — до 1 МиБ UTF-8, документ — до 2 МиБ с реальным JSON escaping. Ошибка/превышение не вызывает усечение материала. Журнал плюс общий source ограничены 1 ГиБ; подготовка имеет конечные бюджеты чтения/записи/сканирования и времени. Бюджет операции не является обещанием срока разработки или гарантией произвольного размера Bank.

## Проверка и визуальная приёмка

```powershell
.\.venv\Scripts\python.exe -X utf8 EXPERIMENTS\object_authoring\runtime\verify_objects.py
.\.venv\Scripts\python.exe -X utf8 EXPERIMENTS\first_bank\verify.py --integration-only
```

Эти проверки используют свои временные данные и процессы, без открытия основного desktop. Визуальная приёмка ожидает пользовательского запуска: создание трёх типов, порядок/пины ссылок, редактирование четырёх типов, старая/новая версия и оригинал, конфликт, повторное открытие, статусы/отмена/закрытие и обновление второго окна. Проверять скриншот нужно при конкретной визуальной проблеме. Первая FUB10 и новая OBJ10/OBJ11 визуальные части остаются явными. Полные R1/research/provider/Watch/restore/hardware/release этой реализацией не приняты.
