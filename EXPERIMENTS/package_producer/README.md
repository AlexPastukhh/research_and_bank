# Prepared R1 package producer

`producer.py publish|inspect|resume --intake-root ABSOLUTE --source-root ABSOLUTE --transaction-id UUID` publishes a prepared private local draft. Supported runtime: Windows/NTFS; Linux mode is explicitly a trusted synthetic fixture, never production fallback.

Both roots must already exist, be private, absolute and disjoint. `source/<transaction_id>/DRAFT.json` is closed `local-bank-draft/1` helper input, preserving existing full-revision envelope fields except that `files` lists exact relative payload paths. `draft.schema.json` describes it. This helper does not create canonical types, allocate IDs, infer timestamps, fetch locators, initialize Bank, mutate SQLite, perform accepted-reference/CAS checks or create accepted receipts. Payload documents/original bytes are copied without reserialization. Manifest UTF-8 is deterministic: sorted keys and file descriptors, no generated values.

Publication uses exclusive transaction directory and exclusive file creation. Input inventory and all supported document/schema/Asset byte descriptors validate before destination creation. Source files stay pinned through native unchanged reader handles; own target directory leases permit read/write sharing with no delete sharing, private ACL/final-path/reparse validation. Exact copied hashes and inventory validate before marker publication. Files flush and close; `READY.pending` is flushed and atomically renamed within its folder by actual `MoveFileExW(flags=8)` without replace/copy flags. Existing files are never replaced. Trusted owner/operator/code and configured root parents are prerequisites; this is not a defence against malicious administrator or same-owner code.

`publish` returns `INCOMPLETE` for an existing unfinished folder and does not fill/rewrite it. `resume` only renames a fully verified exact pending generation matching the same prepared source; missing or changed payload is never repaired. `inspect` needs intake only and verifies retained complete bytes; it does not require the old source. Stable transaction/object/revision IDs remain the caller's responsibility. Published package validity is distinct from Bank acceptance: external references, stale bases, derivation cycles and durable accepted receipt remain app checks.

A post-move exception/cancellation/result-conformance failure returns `UNKNOWN`; lost stdout exits4. Inspect the same transaction, then use existing command adapter and `receipt.get`; do not allocate replacement retry IDs. Busy publication returns exit3, other rejected/incomplete outcomes exit2, cancellation before move exit130, verified published/already-published exit0. Closed publication result is `result.schema.json`; malformed CLI/configuration returns a small CLI error without argument/body echo. Diagnostics do not fabricate an accepted receipt.

Bounded metadata/work/time/directory/output limits are in `LIMITS.json`; existing intake policy/schema limits still apply, including file64MiB/package256MiB. Oversized inputs fail before copy where possible; budget failure after creating an owned folder leaves visible incomplete bytes. No automatic cleanup, quarantine reclamation or durable failed-attempt ledger is supplied. An incomplete folder without a complete matching pending generation requires separately scoped maintenance/new user intent, not a hidden retry.
