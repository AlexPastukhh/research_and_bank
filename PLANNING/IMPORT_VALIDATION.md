## Подтверждённая проблема исходной системы: MAP-WIN-001

Цель: сгенерированная карта должна совпадать с сохранённым контрактом на поддерживаемой платформе.

В TOOLS/generate_system_map.py classify() использует существование пути для классификации ссылки. На Windows логическая capability "tests" совпадает с физическим каталогом TESTS. Генератор меняет type соответствующего узла с logical_capability на system_file; сохранённая карта содержит logical_capability.

Минимальный сценарий:
1. Распаковать неизменённый исходный пакет на Windows с обычной файловой системой без различения регистра.
2. Установить jsonschema и вызвать TOOLS/generate_system_map.py --check.
3. Получить SYSTEM MAP PARITY: FAIL — REFERENCE/SYSTEM_MAP.json.

Независимый diff ожидаемой и построенной карты подтвердил единственное различие:
- node id: tests
- сохранённый type: logical_capability
- Windows-generated type: system_file

Влияние: локальное падение проверки карты, валидатора и соответствующего теста use_cases. Это не повреждение переноса и не доказательство поломки остальных функций. Runtime regressions, golden_paths и phase_records в коротком наборе прошли.

Исправление классификации требует отдельного изменения принятой системы с регрессией и обновлением release integrity. Сам перенос сохраняет исходную систему, поэтому проблему записали, а исходные файлы не изменяли. Вернуться перед работой над генератором карты или перед следующим принятием релиза с поддержкой Windows; без исправления parity gate останется красным.
