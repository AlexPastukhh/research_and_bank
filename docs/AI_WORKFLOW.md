# Работа через ChatGPT и Туннель

Основной actor — ChatGPT по запросу пользователя. Приложение хранит результат между чатами и проверяет команды. Подключение остаётся: ChatGPT → Secure MCP Tunnel → Desktop Commander → Windows HOST, app://asdk_app_6ac4ae16f7e081919a02522c365b34bb. Другой транспорт/remote desktop не вводится.

Обычный желаемый путь: ИИ читает определения/актуальные объекты → уточняет только существенную неоднозначность → готовит данные/правило → валидирует → выполняет разрешённую операцию → проверяет receipt/фактическое сохранение → возвращает ID результата и ограничения. Новому чату доступны определения, правила и происхождение без восстановления переписки.

| Сейчас | Целевой путь |
| --- | --- |
| producer + закрытые intake/query контракты, local command adapter | операции чтения/создания/изменения определений типов и произвольных объектов |
| accepted receipt, revision/conflict/replay, originals | тот же подтверждаемый смысл для новой модели, плюс правила и JSON результатов |
| ограниченный exact/lexical поиск | поиск по настраиваемым полям/тегам/ссылкам по проверенному контракту |

Целевой API пока не реализован: не придумывать работающие create_type/update_field команды. Действующие команды и пределы: [command adapter](../EXPERIMENTS/local_command_adapter/README.md), [read API](../EXPERIMENTS/bank_read_api/README.md), [runtime редакторов](../EXPERIMENTS/object_authoring/runtime/README.md). На UI сейчас не работать.

Повтор после timeout: результат UNKNOWN → проверить receipt и сохранённое состояние → повторить ту же транзакцию только по правилам idempotency. Не создавать новый ID вслепую. Чтение не запускает скрытый пересчёт, новое исследование или внешнюю загрузку (ANTI-014). Изменение/исследование требует применимого разрешения, а вычисленный ответ должен сообщать freshness.

Пользовательские типы и JSON/Markdown-текст можно менять через ИИ. Доверенное Python-правило — исполняемый код, ему нужны review и ограниченные входы; текст материала не является разрешением выполнить код. Права, privacy и payload limits не исчезают от работы через Туннель.

Для разработки: [workflow](../PLANNING/DEVELOPMENT_WORKFLOW.md). Everyday — точечные действия; snapshot — массовая локальная работа; Large Files — отдельно разрешённая передача данных, не изменение инфраструктуры. Перед применением сверяются HOST hashes, после — bytes/receipt и реальные релевантные проверки. Основной desktop не автоматизировать, общий Туннель не перезапускать. Git commit/push не следуют автоматически из сохранения файлов.
