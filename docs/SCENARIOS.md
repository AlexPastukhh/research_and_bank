## SC-075 — Задать тип и наполнить объекты

Need N-PRODUCT-002, N-001/002/008; FR-PRODUCT-002/003, ANTI-007/009. Status candidate; не уже выполненная возможность.

Контекст: пользователь хочет вакансии с фиксированными полями и тегами либо другой собственный тип. Prerequisites: доступ к Bank, разрешение на изменения, описание полей и совместимая схема. Inputs: определение типа, JSON/Markdown-текст, tags/refs/materials.

Путь: ИИ сохраняет и валидирует определение → создаёт/изменяет объекты этого типа → возвращает их ID и receipt → повторно находит/читает те же данные. Ошибки обязательных полей понятны; нет обязательного research/project/создания второй версии.

Outcome: структурированные объекты пригодны для следующей работы и доступны после restart/новому чату. Success: поля/refs/байты/происхождение сохранены, invalid input не принят, старые объекты не повреждены. Composition: SRU-043 → SRU-044 → существующие SRU-002/003 (хранение/чтение). Детали реализации не зашиты в Scenario.

## SC-076 — Получить поле, зависящее от других данных

Need N-003/006/008 + candidate/inferred потребность в вычислениях; FR-002/004/009/020. gendocen — Proposal, не prerequisite пользователя.

Контекст: поле стоимости зависит от hours/rate, либо результат обработки JSON используется дальше. Prerequisites: определённые объекты/поля, разрешённое проверенное правило и доступные inputs. Путь: ИИ задаёт правило → вычисляет → получает JSON с основанием/freshness → меняет нужный input → проверяет новый результат. Читать уже сохранённый результат можно без скрытой mutation.

Outcome: проверяемый результат с входными версиями; отсутствующие данные/цикл/stale publish дают явный отказ. Success: использованный вход влияет, посторонний не создаёт необоснованный пересчёт; после restart нет ложного fresh. Composition: SRU-045 → SRU-046 → SRU-002/003. Смысловой AI-текст отмечается review_required, не переписывается автоматически.
