# Направление развития

Статус: candidate outcome-plan, версия 1.0.0. Поручение обновить документы разрешает их запись; не является командой сейчас мигрировать Bank, принимать gendocen или менять UI. Полный MVP и TARGET сохраняются через [OUTCOME_MAP](OUTCOME_MAP.json); старые R0–R8 — историческое распределение.

| Направление | Observable outcome | Зависимости / переход |
| --- | --- | --- |
| NEXT-01: data/dependency probe | ИИ создаёт временный type + records + rule, получает JSON, повторно читает данные/evidence новым процессом | Проверить [карточку](../PLANNING/WORK_ITEMS/NEXT_GENERIC_DATA_PROBE.json); её evidence определяет следующую архитектуру |
| NEXT-02: generic Bank operations | Создать/прочитать/найти/изменить объект любого определённого типа; ID/теги/refs/байты/history/conflict сохранены | После пробы уточнить schema/совместимость; один реальный vertical slice до полной миграции |
| NEXT-03: durable dependencies | JSON с результатом и freshness/provenance, правила и зависимости переживают restart; stale publish не принимается | Опирается на данные/операции NEXT-02; общий foundation считать один раз |
| NEXT-04: research/reuse | Источники и policy, Lens → immutable RunSpec → Run → исторические ResultSet/Occurrence; два сравнимых запуска и повторное использование | NEXT-02 и нужная часть NEXT-03; MVP-004…008/011 остаются обязательными результатами |
| Далее по evidence | Богатый поиск, identity, измерения, Watch, мультимодальность, domain packs | Конкретная пользовательская ценность, данные, активные COND gates; детали перед выполнением |

UI, представления, рендер/Markdown-экспорт — deferred до явного возврата пользователя. Обязательные результаты поиска/истории/приватности не отменены этой паузой. Не путать экспорт с хранением Markdown-строки или выдачей JSON операции.

NEXT-01 не заменяет MVP и не обещает рабочий универсальный Bank. Он проверяет развилку core adapter/full runtime и схему эволюции до дорогостоящего перехода. Outcome можно опровергнуть; отрицательный результат полезен, если сохранены evidence и новый Proposal. Full-now требует неизвестных решений миграции/persistence; staged сохраняет возможность их изменить. Количественный delta unknown.

Сроки, бюджет, исполнители и hard deadline не установлены. Effort и elapsed time неизвестны; критический путь пока определяется результатом пробы и следующими решениями, не суммой R-номеров. Не придумывать часы или объявлять feasibility. Будущие направления описываются outcome/dependencies/trigger, подробная карточка — только ближайшая.

Новая задача оформляется после проверки её scope и inputs, а не запускается автоматически по порядку таблицы. [Процедура разработки](../PLANNING/DEVELOPMENT_WORKFLOW.md). Определять done отдельно для системы, приложения и фактической приёмки.
