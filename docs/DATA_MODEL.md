# Модель данных

Статус: целевая модель по пользовательским уточнениям; конкретная новая схема и миграция — candidate. Реальный ограниченный профиль описан в [CURRENT_STATE](CURRENT_STATE.md).

| Слой | Смысл |
| --- | --- |
| Определение типа | Устойчивый ID, схема полей, обязательность, допустимые значения/ссылки; история изменений определения |
| Объект | ID, ссылка на определение типа, заполненные поля; общие provenance/история/конфликтная версия отдельно от доменных полей |
| Значение поля | JSON-значение: текст, число, bool, список, структура; Markdown может храниться строкой |
| Материал | Файл/оригинальные байты или locator; ссылка не означает, что удалённый оригинал сохранён |
| Связь | Ссылка на объект/поле/материал; режим head либо pinned должен быть явным |
| Правило | Проверяемое вычисление и его входы; отдельно от простой связи объектов |
| Производное состояние | Результат, входные версии, происхождение и актуальность; AI-текст имеет статус смыслового пересмотра |

Все прикладные типы настраиваемые. Системные metadata и contracts операций могут быть фиксированными. Имена ниже — возможные определения типов, не встроенные enum. Пустая заметка со ссылкой на другой объект не обязательна: самостоятельная идея сама является объектом целевой модели. Коллекция — объект со ссылками/критерием отбора; создание копии каждого участника не требуется.

| Пример | Поля и использование |
| --- | --- |
| Вакансия | title, URL, salary/range, skills, tags, source refs; отдельно наблюдение с временем и исследование с результатами |
| Игра | title, platform, mechanics, visual refs, notes; результат прошлого исследования можно связать и использовать снова |
| Проблема/решение | вопрос, ограничения, варианты, основания, conclusion, status; стоимость варианта может зависеть от числовых полей |
| Учебный материал | Markdown-текст, темы, ссылки на теорию/задачи/решения; исходный текст сохраняется, рендер не входит в этап |

Источник поиска и прошлый исследовательский результат могут быть связанными объектами. Ссылка на результат не делает его новым независимым свидетельством; AI-пересказ не становится первичным источником. Определение типа задаёт структуру, исследовательская роль — применение объекта.

Candidate envelope: id + type_ref + fields + provenance + revision/CAS. Точное имя/формат полей, validation dialect, неизвестные поля, schema evolution и head/pinned defaults выбираются после пробы. Изменение схемы не должно молча инвалидировать или перезаписывать старые записи: сначала чтение/валидация совместимости и план перехода.

История — сквозной механизм первого сохранения и изменений. Обычная работа обычно начинается с единственного состояния; создание дополнительной версии не является обязательным пользовательским шагом. Старый профиль Asset/Entity/Annotation/Collection и intake/query продолжают действовать до проверенного отдельного перехода. Не переименовывать их байты или SQLite-таблицы документационной правкой.
